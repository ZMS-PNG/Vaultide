# 风险、测试与验收矩阵

> 状态：`Proposed`  
> 原则：没有可复现证据就不宣称完成；学习价值、安全性和可恢复性都是发布条件

## 1. 风险分级

- 影响：`1` 可忽略、`2` 局部、`3` 阻断核心流程、`4` 数据/安全/学习价值严重受损。
- 可能性：`1` 罕见、`2` 偶发、`3` 常见、`4` 高概率。
- 分数 = 影响 × 可能性；`12–16` 为 Critical，`8–11` 为 High，`4–7` 为 Medium。
- Critical/High 风险没有验证证据时不得进入个人正式版。

## 3. 开工前安全基线

当前仓库快照使用 React `19.2.3`、Next.js `16.1.2`。截至 2026-07-20，React 官方已发布更新版本并明确修补 React Server Components 后续问题；Next.js 官方安全公告也包含晚于当前版本的修复。因此，**依赖升级是 Gate 0 的硬前置，不是上线后的优化**。

执行规则：

1. 重新核对 [React 官方版本页](https://react.dev/versions)、[React RSC 安全更新](https://react.dev/blog/2025/12/11/denial-of-service-and-source-code-exposure-in-react-server-components) 和 [Next.js 官方安全公告](https://github.com/vercel/next.js/security/advisories)。
2. 升级到当时官方支持且覆盖已知公告的 React/Next 稳定版本，不在本文冻结具体未来版本号。
3. 保留锁文件，运行构建、现有测试、课堂生成、播放器和导入导出回归。
4. 对生产配置执行依赖扫描；Critical/High 已知漏洞若无官方缓解措施则阻断发布。
5. 记录升级 ADR、兼容性变化和回退 commit。

## 4. 测试策略

### 4.1 测试层次

| 层次 | 重点 | 每次 PR | 发布前 |
|---|---|---:|---:|
| 领域单元测试 | 状态机、掌握投影、复习规则、路径规则、幂等 | 必须 | 必须 |
| Schema/契约测试 | API、事件、命令、插件兼容 | 必须 | 必须 |
| Repository 集成测试 | Postgres 事务、唯一约束、Outbox/Inbox、删除 | 相关改动 | 必须 |
| 存储/工作流集成测试 | 私有直传、checksum、重试、取消、checkpoint | 相关改动 | 必须 |
| 插件测试 | 选源、缓存、冲突、移动端兼容、凭证迁移 | 相关改动 | 必须 |
| 端到端测试 | 配对到回写与复习的黄金路径 | 冒烟 | 全量 |
| 学习质量评估 | 引用、提示策略、rubric、迁移表现 | 样本变更 | 固定评测集 |
| 安全/隐私测试 | 越权、注入、泄露、路径、删除 | 安全相关 | 全量 |
| 故障注入 | 断网、重复投递、工作流中断、旧客户端 | 否 | 必须 |

### 4.2 固定测试夹具

建立独立测试 Vault，不使用真实个人 Vault。至少包含：

- 普通 Markdown、frontmatter、标题、块 ID、wiki link、embed、Unicode 路径；
- 重名笔记、移动/重命名笔记、100 KB 大笔记和 10 MB Bundle；
- 含提示注入文本、HTML、恶意 ZIP 路径、超深链接和损坏附件；
- 受管笔记在草稿生成后被外部编辑的冲突样本；
- 三个学习主题：事实回忆、概念解释、真实项目迁移。

测试 Vault 必须与日常 Vault 分离，并可从版本库完全重建。

## 5. 黄金端到端场景

### E2E-01：首次闭环

1. Web 创建配对 code，插件显示设备/Vault 信息并成功配对。
2. 用户创建真实 Project、Blocker、交付物和验收标准。
3. 插件只打包选中的 3 篇笔记；Web 可核对每个来源和 hash。
4. 持久 Job 完成诊断、冲刺计划和 OpenMAIC 课堂；刷新/重新部署后状态仍在。
5. 用户先作答再获得提示，完成练习并提交真实 Evidence。
6. 系统按 rubric 评价，生成带引用的 WritebackDraft。
7. 用户预览、编辑、批准；插件在受管目录创建记录并回传 receipt。
8. 系统生成 ReviewItem；到期后完成一次复习并更新可解释 MasteryView。

通过条件：全过程无人工改数据库；每一步均可从 UI 看见来源、状态、错误或恢复动作。

### E2E-02：断网与幂等

- 在事件提交、Blob 上传完成回调、Job 启动和 receipt 上报四个位置断网。
- 每个请求重复发送 3 次，并重启插件与部署。
- 通过条件：不丢事件、不重复收费型 Job、不重复写 Vault；最终状态一致。

### E2E-03：冲突保护

- 草稿生成后外部修改目标笔记，再批准命令。
- 通过条件：命令标记 `conflicted`，显示差异和恢复选项，目标文件保持外部修改后的内容。

### E2E-04：越权与删除

- 设备 A 尝试读取设备 B/Vault B 的 Bundle、Feed 和 Writeback。
- 撤销设备 A，随后用旧 token、旧直传 URL 和旧下载 URL 重试。
- 发起全量删除并验证 Blob、DB、投影、Feed 和导出。
- 通过条件：所有越权均拒绝；撤销即时生效；删除 receipt 与实际检查一致。

### E2E-05：版本不兼容

- 旧插件收到未知可选字段、未知事件和未知写命令。
- 通过条件：可选字段不破坏读取；未知写命令拒绝并上报；过旧版本得到明确升级提示。

### E2E-06：移动端最小能力

- iOS/Android Obsidian 真机完成配对、3 篇 Markdown 选源、状态查看和新建受管记录。
- 通过条件：无 Node 专用 API；应用切后台/恢复不损坏队列；受系统限制的后台同步有明确提示。

## 6. 学习质量评测

### 6.1 固定评测集

每个主题至少设计：

- 3 个来源内事实问题；
- 2 个需要综合多个来源的解释问题；
- 2 个带常见误区的诊断题；
- 1 个必须落到真实交付物的应用任务；
- 1 个改变表面情境的迁移任务；
- 明确的理想答案、可接受边界、引用和 rubric。

人工盲评维度：来源忠实度、教学顺序、提示泄漏、反馈可操作性、证据真实性、迁移难度和安全性。

### 6.2 P0 学习价值阈值

首批个人试用至少完成 10 个有效闭环后再判断：

- ≥ 80% 的课堂关键主张具有可打开的来源引用；
- ≥ 90% 的互动在展示完整答案前记录过用户尝试，明确选择“直接看答案”的除外；
- ≥ 70% 的冲刺在 48 小时内产生真实 Project Evidence；
- ≥ 70% 的 Evidence 达到预设 rubric 的最低通过线；
- 延迟迁移任务表现相对首次诊断有改善，并记录原始样本而非只看平均分；
- 用户主观负担没有因复习队列持续上升。

阈值用于发现方向问题，不用于伪造统计显著性。单人阶段重点看连续样本、失败案例和行为变化。

## 7. 安全与隐私测试清单

### 7.1 身份与授权

- token 过期、撤销、作用域不足、device/vault 不匹配；
- owner 资源枚举、ID 替换、批量接口混入他人 ID；
- 配对 code 重放、暴力尝试、错误设备确认；
- `learnerKey` 伪造不能带来任何额外权限。

### 7.2 内容与模型边界

- 来源中嵌入系统提示、工具调用要求、数据外传 URL 和伪造引用；
- 模型输出未知 writeback operation、绝对路径、`../`、脚本和超大正文；
- 检查系统 prompt、token、私密原文不会进入客户端错误或第三方遥测；
- 引用缺失、引用不支持主张、来源快照过期时必须降级或提示。

### 7.3 上传与文件

- zip slip、压缩炸弹、重复文件名、MIME 欺骗、checksum 不符、断点重放；
- 受管目录外路径、符号链接逃逸、大小写/Unicode 规范化碰撞；
- 目标文件正在修改、被删除、只读或 Vault 关闭时的安全失败。

### 7.4 删除与数据泄露

- 删除后旧签名 URL、缓存和 search index 不可访问；
- 日志、trace、分析事件、错误追踪和备份策略不含未声明正文；
- 导出只包含当前 owner，且 secrets/token 被排除或遮蔽。

安全设计以 [OWASP LLM Prompt Injection Prevention](https://genai.owasp.org/llmrisk/llm01-prompt-injection/) 为最低检查基线，但必须结合本系统的 Vault 写回边界测试。

## 8. 可靠性与性能验收

### 8.1 SLO 候选

| 指标 | P0 目标 |
|---|---:|
| 已接受 API 请求的领域记录耐久性 | 99.99% |
| 24 小时内持久 Job 终态率 | ≥ 99%（排除用户取消） |
| 同步消息最终处理成功率 | ≥ 99.5% |
| 重复回写副作用 | 0 |
| 未检测到的原文覆盖 | 0 |
| 普通 API p95 | < 800 ms，不含模型/上传 |
| 10 篇普通 Markdown 本地打包 | < 3 s（目标设备） |
| Web/插件可见 Job 首次状态 | < 2 s |

SLO 只在有可观测数据后转为正式承诺。每项必须有测量口径、窗口和排除条件。

### 8.2 故障注入

- Workflow 每个步骤前后终止一次；
- Postgres 提交成功但响应丢失；
- Blob 上传成功但 complete 调用失败；
- Feed 重复、乱序、游标过期；
- 模型超时、限流、返回非法 Schema；
- Vercel 新部署切换期间持续操作；
- 插件升级时本地队列存在未确认消息。

每个故障必须得到“自动恢复、用户可恢复或明确终止”之一，不能无限 pending。

## 10. Gate 验收矩阵

| Gate | 必须通过 | 立即停止条件 |
|---|---|---|
| Gate 0 基线 | 依赖安全升级；现有功能回归；数据路径盘点；可复现部署 | 存在未缓解 Critical/High 漏洞；基线无法回退 |
| Gate 1 产品/协议 | PRD、Schema、状态机、权限与保留决策冻结 | 核心闭环或数据权威仍有冲突 |
| Gate 2 探针 | 配对、直传、持久 Job、冲突回写在真实环境通过 | 任一探针只能靠生产不安全捷径完成 |
| Gate 3 骨架 | DB/Blob/Workflow/Outbox/契约测试与观测打通 | 仍依赖本地文件持久化或内存状态 |
| Gate 4 Alpha | E2E-01、02、03；引用可追溯；导出可读 | 有数据丢失、重复收费、静默覆盖 |
| Gate 5 学习价值 | 10 个闭环评测达到学习阈值或明确找到可修正原因 | 只增加内容消费，证据和迁移无改善 |
| Gate 6 个人正式版 | 全量安全、删除、移动端、故障注入、回退演练 | 越权、正文泄露、不可恢复冲突、删除失效 |

## 11. Go / No-Go 决策

只有以下全部成立才可标记“个人正式版”：

- 所有 Critical/High 风险已关闭，或有明确、限时、不会触及数据/安全的豁免；
- 黄金 E2E 在 Production 等价环境连续通过 3 次；
- 已从备份/导出恢复一次完整 Project；
- 已撤销设备并验证旧凭证失效；
- 已执行一次部署回退与一次 Schema 向前修复演练；
- 学习价值阈值有真实个人样本支持；
- PRD、架构、协议、ADR、风险表和已知限制与实现一致。

任何出现未授权外发、Vault 静默覆盖、跨 owner 访问或不可解释的数据丢失，都直接 `No-Go`，先处置再讨论功能进度。
