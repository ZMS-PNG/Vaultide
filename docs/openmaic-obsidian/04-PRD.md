# OpenMAIC × Obsidian 项目学习系统 PRD

> 版本：v1.0 候选  
> 状态：Proposed  
> 产品形态：Vercel 上的 OpenMAIC Web + Obsidian 社区插件/手动安装插件  
> 首要用户：单一 Owner，本人使用  
> 原始指导方向：通过 MAIC 学项目、通过 Obsidian 管理与回写知识、让 MAIC 使用 Obsidian 中的项目资料

## 1. 产品摘要

### 1.1 一句话产品

从用户的真实项目卡点出发，利用其明确选择的 Obsidian 知识，运行一段可验证的 OpenMAIC 学习冲刺，并把经用户确认的经验、错误、证据和复习计划沉淀回 Vault。

### 1.2 核心差异

本产品的差异不是“能问整个 Vault”，而是将以下行为连接成一个可测闭环：

```text
项目问题 → 知识诊断 → 主动学习 → 真实产出
        → 能力验证 → 安全回写 → 延迟复习 → 再次迁移
```

### 1.3 产品承诺

- 不默认扫描或上传整个 Vault；
- 不用课程数量和对话数量冒充学习效果；
- 不允许模型静默写入原始笔记；
- 不把一次 Quiz 分数冒充长期掌握；
- 不替用户完成项目核心交付物；
- 重要输出要么有可定位来源，要么明确标为推断/待验证。

## 2. 背景与机会

OpenMAIC 已具备课程生成、Quiz、互动场景、多智能体讨论和 PBL；Obsidian 已是用户长期管理项目知识的工具。两者目前缺少：

- 项目上下文与学习目标的结构化连接；
- 明确选源、来源版本和段落引用；
- 从课堂行为到真实项目证据的映射；
- 可解释的能力状态和记忆状态；
- 安全、可预览、可撤销的 Vault 回写；
- 延迟复习和未来项目复用；
- 生产可靠的 Vercel 任务与持久化基础。

## 3. 目标与非目标

### 3.1 P0 目标

1. 用户可以从 Obsidian 发起一个与真实项目卡点绑定的学习冲刺。
2. 用户可以明确选择来源，并看见发送范围和每条引用。
3. OpenMAIC 先诊断，再生成 15–45 分钟的最短学习路径。
4. 学习必须包含无提示回忆或生成性练习，以及真实项目动作。
5. 用户可以提交项目证据，并按预定义标准验证。
6. 系统生成结构化回写草稿，经用户确认后写入受管目录。
7. 系统保存学习事件并创建 D1/D7/D30 复习任务。
8. 用户可以撤销设备、导出记录、删除远端数据和恢复回写。

### 3.2 非目标

- 全量自动双向同步；
- 通用个人 AI 助手；
- 完整 Anki 替代品；
- 团队协作或学校 LMS；
- 自动评价任意复杂项目的绝对质量；
- 让模型自主读写整个 Vault 或执行任意本地命令；
- 为每篇笔记自动生成课堂或复习卡。

## 4. 用户画像与场景

### 4.1 Persona：项目型个人学习者

- 已经有 Obsidian Vault；
- 同时推进一个或多个软件、AI、研究或产品项目；
- 学习发生在项目推进过程中；
- 需要减少资料检索、重复学习和经验丢失；
- 愿意接受“先尝试、再提示、最后讲解”的学习方式。

### 4.2 黄金场景

用户开发一个真实功能时遇到技术卡点。他从 Obsidian 选择项目规范、之前的调研和一篇技术笔记，定义本次交付为“实现并通过三个测试”。系统先诊断概念和边界，再生成一个短课堂和练习。用户回到代码仓完成实现，提交测试结果。系统按验收标准反馈，生成一篇包含来源、错误原因、最终决策、代码/测试证据和后续复习题的学习记录。用户确认后写回 Vault，并在 1、7、30 天后完成简短迁移练习。

## 5. 产品模型

### 5.1 三种状态必须分离

| 状态 | 回答的问题 | 事实来源 |
|---|---|---|
| Knowledge State | Vault 中有什么、来源怎样关联、内容版本是什么 | Obsidian 文件和 SourceSnapshot |
| Capability State | 用户能否解释、解决问题和独立完成真实任务 | Attempt、ProjectEvidence、RubricResult |
| Memory State | 某个可检索知识项何时需要复习 | ReviewEvent 与 SchedulerState |

任何一个状态都不能直接替代另外两个。

### 5.2 关键对象

```text
Project
 └─ ProjectBlocker
     └─ LearningSprint
         ├─ SourceBundle → SourceSnapshot → CitationAnchor
         ├─ LearningObjective → Activity → Attempt
         ├─ ProjectEvidence → Evaluation
         ├─ LearningEvent
         ├─ WritebackDraft
         └─ ReviewItem → ReviewEvent
```

## 6. 完整用户旅程

### 6.1 首次连接

1. 用户在 OpenMAIC Web 输入现有 ACCESS_CODE，进入个人站点。
2. 用户打开“连接 Obsidian”，生成 10 分钟有效的一次性配对码。
3. 用户在插件中填写站点 URL 和配对码。
4. 插件展示请求权限：选定来源上传、创建学习任务、读取回写草稿、确认回写结果。
5. 服务端签发设备令牌；插件保存到 Obsidian SecretStorage。
6. Web 显示设备名称、创建时间、最近使用和撤销按钮。
7. 用户选择受管目录，默认 `OpenMAIC/`。

### 6.2 创建项目

用户可在插件中创建一篇受管项目笔记，或把已有笔记关联为项目入口。

必填：

- 项目名称；
- 最终目标；
- 当前阶段；
- 预期交付物；
- 验收标准；
- 当前具体卡点。

选填：截止日期、可用时间、已有能力、自认为的风险、外部资料政策。

### 6.3 选择来源

1. 插件根据当前项目路径、标题、标签、内部链接和关键词在本地建议候选。
2. 用户逐项选择文件；P0 不自动递归选中笔记的所有链接。
3. 用户可限定标题/段落，默认整篇 Markdown。
4. 插件显示：文件路径、字节数、预计 token、附件、敏感提示、远端保留期。
5. 默认外部搜索关闭；用户可选择“仅 Vault”“Vault + 官方资料”“允许一般 Web”。
6. 确认后生成不可变 SourceBundle。

### 6.4 诊断与计划

1. 系统根据交付物、验收标准和来源生成 2–5 个诊断问题。
2. 用户在看讲解前完成首答，或明确选择“不知道”。
3. 系统把目标分为：已具备、需确认、存在缺口、资料不足。
4. 系统生成 15/30/45 分钟计划，显示活动、时间、模型/媒体预算和最终项目动作。
5. 用户可以删除活动或降低媒体成本，但不能删除最终应用任务和验收。

### 6.5 OpenMAIC 学习冲刺

1. 每个活动显示学习目标和来源。
2. 默认采用提示阶梯：重述问题 → 方向提示 → 局部提示 → 示例 → 完整讲解。
3. 用户完成至少一次无提示回忆/解释。
4. 多智能体只用于呈现真实争议、角色权衡或批评；不能用闲聊延长课堂。
5. Quiz 首答不可查看答案，反馈引用支持它的来源。
6. PBL 必须包含真实驱动问题、用户选择、里程碑、量规、批评修订和最终作品。
7. 系统在适当时机明确提示“现在返回真实项目执行”。

### 6.6 真实证据与验证

1. 用户提交文本说明、文件引用、测试输出、URL、截图或结构化检查结果。
2. 系统优先运行确定性检查；无法自动检查时使用用户确认的量规。
3. AI 可以解释证据与标准之间的关系，但不能隐瞒不确定性。
4. 系统必须区分：通过、部分通过、未通过、证据不足。
5. 未通过时优先给下一步诊断或提示，而不是直接替用户完成。

### 6.7 回写

1. 系统生成 WritebackDraft，不拥有直接 Vault 写权限。
2. 草稿至少包含：问题、目标、来源、首答、关键错误、最终决策、项目证据、剩余假设、下一步和复习项。
3. 插件展示 Markdown 预览、目标路径、将创建/修改的内容和引用。
4. P0 默认在 `OpenMAIC/Learning/` 新建受管学习记录；不修改来源笔记。
5. 用户可编辑、接受或拒绝；接受后插件执行并回报结果。
6. 写入失败或目标变化时不覆盖，进入冲突处理。

### 6.8 复习与迁移

1. 用户只确认真正值得长期保持的 ReviewItem。
2. P0 默认 D1、D7、D30；每次包含简短无提示回忆，至少一次新情境应用。
3. 今日队列有时间/数量上限；积压时优先项目相关性和遗忘风险。
4. 用户可暂停、删除、拆分或重写难项。
5. 复习结果追加为事件，并更新可解释的能力/记忆视图。

## 7. P0 功能需求与验收

### 7.1 项目与卡点

| ID | 需求 | 验收标准 |
|---|---|---|
| PRJ-001 | 创建/编辑 Project | 缺少目标、交付物或验收标准时不能启动正式冲刺；草稿可保存 |
| PRJ-002 | 记录当前 Blocker | 必须描述“现状、阻碍、期望结果”；可结束并保留历史 |
| PRJ-003 | Obsidian 项目入口 | 可创建受管项目笔记，或关联已有文件；关联不修改原文件正文 |
| PRJ-004 | 冲刺时间预算 | 支持 15/30/45 分钟；计划总估时超出时必须提醒并允许收缩 |

### 7.2 配对与权限

| ID | 需求 | 验收标准 |
|---|---|---|
| AUT-001 | 一次性设备配对 | 配对码短时、单次有效；使用后和过期后不可重放 |
| AUT-002 | 设备作用域令牌 | 令牌只允许协议声明的来源、任务、回写接口；服务端仅存哈希 |
| AUT-003 | 本地安全存储 | Obsidian 1.11.4+ 使用 SecretStorage；回退路径显式警告 |
| AUT-004 | 撤销与审计 | Web 撤销后，设备下一次请求返回 401/403；审计不记录原文或令牌 |

### 7.3 来源选择与引用

| ID | 需求 | 验收标准 |
|---|---|---|
| SRC-001 | 本地候选召回 | P0 使用路径、标题、标签、链接、关键词；不需要云端全 Vault 索引 |
| SRC-002 | 显式选择 | 未被选择的文件不得出现在上传字节、日志、模型上下文或引用中 |
| SRC-003 | 范围预览 | 上传前显示路径、大小、附件、外发目的、保留期和外部搜索模式 |
| SRC-004 | 不可变快照 | 每个快照带 stable ID、path、mtime、hash、bundle revision；上传后不可原地覆盖 |
| SRC-005 | 段落引用 | 引用至少能定位到文件 + 标题/块 + 快照版本；原文不足时标记证据不足 |
| SRC-006 | 来源变化 | 打包中内容变化则中止；后续变化不篡改旧冲刺，创建新 revision |
| SRC-007 | 生命周期 | 用户可查看、下载和删除远端快照；删除后派生内容按策略处置 |

### 7.4 诊断与冲刺计划

| ID | 需求 | 验收标准 |
|---|---|---|
| DIA-001 | 先诊断后教学 | 正式讲解前保存用户首答；用户可选“不知道”，不能由模型代填 |
| DIA-002 | 缺口分类 | 输出已具备/需确认/缺口/资料不足，并为每项提供证据 |
| DIA-003 | 诊断质量 | 每题映射一个 LearningObjective；不能只考来源原句识别 |
| SPR-001 | 最短计划 | 每个活动说明目标、形式、估时、来源和完成条件 |
| SPR-002 | 必含活动 | 至少包含主动回忆、项目应用和结果验证，用户不能全部删除 |
| SPR-003 | 成本预算 | 生成前显示模型、媒体开关和估算预算；达到上限时降级而非失控调用 |

### 7.5 课堂与辅导行为

| ID | 需求 | 验收标准 |
|---|---|---|
| LRN-001 | 复用 OpenMAIC 场景 | 使用现有 slide/quiz/interactive/PBL 契约，不创建不兼容平行课堂格式 |
| LRN-002 | 来源约束 | 来源事实有 citation；模型推断有显式标签；冲突来源同时呈现 |
| LRN-003 | 提示阶梯 | 默认不直接泄露完整答案；保存提示级别和用户每次尝试 |
| LRN-004 | 主动回忆 | 每个关键目标至少有一次不看材料的解释、重建或解题 |
| LRN-005 | 多智能体节制 | 每个角色必须有独立教学目的；无增益时使用单导师 |
| LRN-006 | 中断恢复 | 刷新、断网或任务重试后能从已提交事件恢复，不重复活动 |
| LRN-007 | 资料不足 | 不编造答案；显示缺失信息并允许用户增加来源或授权官方检索 |

### 7.6 项目证据与评价

| ID | 需求 | 验收标准 |
|---|---|---|
| EVD-001 | 提交真实证据 | 支持文本、文件/代码引用、测试结果、URL、图片元数据；大文件走对象存储 |
| EVD-002 | 预定义量规 | 量规在任务执行前可见；提交后不能静默改变通过条件 |
| EVD-003 | 评价优先级 | 自动测试/确定性规则优先，人工量规其次，LLM 只做有依据的辅助 |
| EVD-004 | 结果分级 | 仅允许通过/部分通过/未通过/证据不足；显示每条标准与证据 |
| EVD-005 | 独立性 | 记录提示后是否由用户独立完成；AI 直接生成的产物不能自动计为用户能力证据 |

### 7.7 回写与冲突

| ID | 需求 | 验收标准 |
|---|---|---|
| WBK-001 | 结构化草稿 | 草稿带来源、目标路径、baseHash、operation、协议版本和 idempotencyKey |
| WBK-002 | 人工确认 | 未确认前 Vault 写操作为 0；拒绝后服务端不得再次自动推送同一草稿 |
| WBK-003 | 默认新建 | P0 写入受管目录；路径冲突时提示或生成可预测后缀，不覆盖 |
| WBK-004 | 原子写入 | 使用 Vault/FileManager 官方 API；并发变化时停止并显示冲突 |
| WBK-005 | 幂等 | 同一草稿确认多次只产生一次逻辑写入和一个结果事件 |
| WBK-006 | 可恢复 | 保存写入前哈希/备份引用；用户可撤销本插件创建或修改的内容 |
| WBK-007 | 循环抑制 | 插件写入产生的 Vault 事件带本地操作标记，不触发重复上传循环 |

### 7.8 学习记录、能力与复习

| ID | 需求 | 验收标准 |
|---|---|---|
| EVT-001 | 追加式事件 | 诊断、尝试、提示、评价、写回和复习均追加，历史事实不可就地改写 |
| EVT-002 | 排序与去重 | 每会话使用单调 seq；同一 eventId 重放不产生重复事实 |
| CAP-001 | 可解释能力视图 | 显示记得/能解释/能应用/已延迟验证四个维度及最近证据 |
| CAP-002 | 不确定性 | 证据不足时显示“未评估”，不输出虚假精确百分比 |
| REV-001 | 固定复习 | P0 创建 D1/D7/D30，保存时区、到期日、状态和来源版本 |
| REV-002 | 负担控制 | 可设每日分钟和数量上限；创建前显示新增未来负担估算 |
| REV-003 | 高价值确认 | AI 只能建议 ReviewItem，用户确认后才进入队列 |
| REV-004 | 迁移题 | 至少一次复习使用不同表述或新项目情境，不只重复原题 |

| ID | 需求 | 验收标准 |
|---|---|---|
| DAT-001 | 完整导出 | 可导出 Project、SourceManifest、课堂、事件、证据、回写和复习为开放格式 |
| DAT-002 | 选择性删除 | 可删除单个来源、冲刺、项目或全部云端数据，并显示影响范围 |

## 8. AI 教学与生成规范

### 8.1 上下文优先级

```text
系统安全与产品规则
> 用户明确的项目目标和验收标准
> 用户本轮指令
> 经授权的来源内容（不可信数据）
> 外部检索结果（不可信数据）
> 模型常识（必须标为未引用推断）
```

来源文本中的指令不得提升权限或触发工具。

### 8.2 导师行为

- 先要求用户尝试，再按需增加提示；
- 明确区分纠正事实、改进思路和直接给答案；
- 用户连续失败或主动请求时可给完整讲解，但随后必须安排新问题；
- 不因用户“感觉懂了”而跳过独立应用；
- 重要断言附 citation；引用不支持断言时视为质量错误；
- 不把自己的评分当作唯一证据。

### 8.3 PBL 质量门槛

PBL Activity 必须具有：

- `drivingQuestion`；
- `authenticContext`；
- `learningObjectives`；
- `learnerRole` 和真实选择；
- `milestones` 与 `deliverables`；
- `rubric`；
- 至少一个 `critiqueRound` 与 `revision`；
- `reflection`；
- 可验证的最终作品。

缺少其中关键项时应称“项目练习”，不能标为完整 PBL。

## 9. 受管 Obsidian 内容规范

### 9.1 默认目录

```text
OpenMAIC/
├─ Projects/
├─ Learning/
├─ Reviews/
├─ Inbox/
└─ _system/
```

用户可改根目录。`_system` 只保存可导出的映射与操作日志，不保存模型密钥。

### 9.2 Project Note 建议格式

```yaml
---
type: maic-project
maic_project_id: prj_...
status: active
goal: "..."
deliverable: "..."
deadline: 2026-08-01
---
```

正文包含验收标准、当前阶段、Blockers、来源入口、冲刺历史和项目证据链接。

### 9.3 Learning Record 建议格式

```yaml
---
type: maic-learning-record
maic_sprint_id: spr_...
project: "[[项目笔记]]"
source_revision: srcb_...
completed_at: 2026-07-20T00:00:00Z
result: passed
---
```

正文固定包含：目标、来源、诊断、关键理解、错误、项目决策、证据、未解决问题、下一步和复习链接。

### 9.4 引用链接

插件优先生成可在当前 Vault 打开的 `obsidian://open` 或标准 wikilink，并在元数据中保留快照 anchor。显示链接和持久身份分离，避免把文件路径当唯一 ID。

## 10. 能力视图

### 10.1 状态

```text
unassessed
→ diagnosed
→ practicing
→ applied
→ verified
→ needs_review
```

状态可因新证据前进，也可因延迟失败进入 `needs_review`。历史事件不被覆盖。

### 10.2 四维证据

| 维度 | 最低证据 |
|---|---|
| Recall | 无提示回忆关键内容 |
| Explain | 用自己的话解释并处理追问 |
| Apply | 在真实或高度同构任务中应用 |
| Retain/Transfer | 延迟后在新表述或新情境中成功 |

“verified”至少需要 Apply；长期“稳定掌握”的展示需要 Retain/Transfer。P0 不显示带小数的单一掌握百分比。

## 11. 非功能需求

### 11.1 隐私与安全

- 最小选源、默认不递归、默认外部检索关闭；
- 模型 Key 只在服务端；设备令牌最小权限、可撤销、可轮换；
- 原始笔记、模型输入和完整输出不得进入普通日志；
- Private Blob 保存来源和私有证据；签名 URL 短时且绑定 owner；
- 全部对象按 owner 分区，所有查询强制 owner 条件；
- 来源和模型输出均视为不可信，防提示注入和不安全 HTML；
- 写回、删除和执行始终需要确定性检查，危险动作需确认；
- 插件 README 披露网络、账户、外发、保留期和服务端实现。

### 11.2 可靠性

- 长任务跨 Function 重启和部署恢复；
- 至少一次执行语义下所有步骤幂等；
- 任务状态持久化，支持取消和有限重试；
- Web/插件离线时不丢已确认本地操作；
- 数据库使用约束和事务，不以进程内锁作为一致性保障；
- API 兼容当前和前一协议版本；
- 数据库和协议迁移使用 expand/contract。

### 11.3 性能目标（P0）

- 插件空闲启动新增阻塞时间目标 < 100 ms；昂贵工作在 `onLayoutReady` 后执行；
- 1,000 篇笔记的元数据候选筛选目标 < 1 s，不读取全部正文；
- 选择 10 篇普通 Markdown 后，SourceBundle 本地生成目标 < 3 s；
- 配对和普通状态 API P95 < 1 s（不含网络异常）；
- 创建任务后 1 s 内返回持久 jobId；
- 用户可在 5 s 内看到任务第一条状态；
- 回写确认后本地操作目标 < 2 s；
- 不把“课堂全部生成完”设为固定秒数 SLO，而分别监控每个步骤和模型延迟。

### 11.4 移动端与无障碍

- 插件 P0 不使用桌面专用 API；若功能确需桌面能力，单独降级并说明；
- 键盘可完成选源、确认和复习；
- 所有交互有可见焦点、语义标签、足够点击区域和明暗主题兼容；
- 动画遵循 reduced-motion；
- 网络中断后可恢复草稿和状态；
- 中文为首要界面语言，协议内容保持 Unicode 和时区安全。

### 11.5 可观测性

- 业务关联键：requestId、jobId、projectId、sprintId、deviceId；
- 指标：步骤延迟、重试、失败分类、模型 token/费用、Blob/DB 操作、冲突次数；
- 用户侧能看到任务步骤和可执行错误；
- 不使用未披露的第三方客户端遥测；学习指标作为用户一方数据保存，可导出/删除。

## 12. 指标与实验

### 12.1 结果指标

| 指标 | 定义 |
|---|---|
| Time to Effective Practice | 从记录 Blocker 到首次有效主动练习的时间 |
| Time to Verified Task | 从 Blocker 到项目证据满足验收的时间 |
| Valid Loop Rate | 启动的冲刺中完整满足七项闭环条件的比例 |
| Independent Next-task Rate | 接受帮助后，下一同构/迁移任务无额外帮助完成的比例 |
| D7 Recall/Transfer | 7 天后无提示回忆与迁移任务结果 |
| Repeat-help Rate | 同类问题在设定周期内再次求助比例 |
| Writeback Acceptance | 草稿被接受、编辑后接受、拒绝的比例和编辑耗时 |
| Reuse Rate | 回写知识在未来项目被检索并成功使用的比例 |
| Total Overhead | 学习 + 选源 + 等待 + 整理 + 纠错 + AI 返工时间 |

### 12.2 质量指标

- citation coverage、citation correctness；
- unsupported claim rate；
- answer leakage rate；
- 任务重试成功率和重复副作用率；
- 回写冲突率、误覆盖率；
- 源快照删除完成率；
- 每次完整冲刺费用分布。

### 12.3 首批实验

1. “主题生成课程” vs “项目卡点学习冲刺”；
2. “先讲解” vs “先诊断和尝试”；
3. 单导师 vs 有明确争议目的的多智能体；
4. 只做即时 Quiz vs 增加真实项目证据；
5. 无回写 vs 受管结构化回写；
6. 无复习 vs D1/D7/D30。

单用户情况下采用交替任务和时间序列，而不伪装成大样本统计结论。

## 13. P1 需求

- Vault 事件驱动的增量同步、重命名和删除标记；
- 本地混合检索与可选向量索引，索引带 embedding/chunking 版本；
- 对已有笔记进行三方合并、逐块接受和回写撤销；
- FSRS 适配、目标保持率和每日负担模拟；
- 项目截止日期与长期保持双目标调度；
- Git、测试、CI、Figma/设计、实验结果证据适配器；
- 显式概念/先修图和可解释能力追踪；
- 多设备状态同步与匿名身份合并；
- Anki、Obsidian Spaced Repetition 和普通 Markdown 导入导出；
- 模型路由、预算策略和本地模型模式。

## 14. P2 需求

- 可选本地网关，使敏感来源不离开设备；
- 复杂离线课堂与离线复习；
- 团队/导师协作与共享量规；
- 领域内容模板市场；
- 经充分验证后的长期自主学习代理；
- 大规模学习策略实验平台。

这些能力不能提前污染 P0 数据模型，但架构需预留 owner/tenant、版本和端口。

## 15. 依赖与约束

- OpenMAIC 上游版本变化和 DSL 迁移；
- React/Next 官方支持周期、安全公告与升级兼容性；
- Obsidian API 版本、SecretStorage 最低版本和移动端差异；
- Vercel Workflow、Blob、Function 与 Marketplace 数据库限制；
- 模型提供商成本、上下文和数据政策；
- 用户自己的 Vault 同步工具可能造成并发修改；
- 单用户实验不能外推为普适教育效果。

## 16. 发布条件

P0 Production 必须同时满足：

- [实施流程 Gate 0–6](./03-IMPLEMENTATION-FLOW.md)；
